# upstream/map.md — limba → mova, file by file

> The porting contract. Every file limba tracks appears here with its mova destination and
> the transform applied on the way. `playbooks/sync-upstream.md` resolves each new `PORT-NNN`
> entry in limba's `docs/logs/porting_log.md` against this table; a limba file missing from
> this table is a sync error, not a judgment call. Locked position: `upstream/limba.lock`.

**Transforms:**
- `verbatim` — port as-is (path may change).
- `param` — structure ports; named specifics move to the profile config block or the pack.
- `split` — one limba file becomes two+ mova files (engine half + pack/instance half).
- `template` — limba's file is personal content; its *shape* becomes a `setup/templates/`
  scaffold that setup regenerates per learner.
- `design-input` — not ported; informs a mova feature named in Notes.
- `skip` — personal history or limba-only plumbing; downstream never needs it.

## Lineage

mova forks limba's machinery the way limba forked vibecoding-starterpack — but with this map
kept total and a live porting feed, because limba is still moving. Three deliberate
inversions relative to limba: AGENTS.md is canonical (multi-agent audience), the learner
profile is one file with one machine-readable block (limba: four prose copies + one regex),
and skills' bodies live agent-neutrally in `playbooks/` (limba: Claude Code skills).
